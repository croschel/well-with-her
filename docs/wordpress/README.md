# WellWithHer on WordPress (Hostinger)

The site is being rebuilt as a WordPress site on Hostinger so the wife can run it alone, without a
developer. This repo (Next.js + Payload) stays as the design and content reference, and as the
fallback if the WordPress version doesn't work out. This doc records why we moved, what was built
in WordPress, every non-obvious decision, and what's still open.

Snapshot as of 2026-10-10.

## Why WordPress (and not Next.js on Hostinger)

The goal was to cut hosting cost versus Vercel Pro (see [`hosting-decision.md`](hosting-decision.md)
for the cost comparison). The first attempt was deploying this Next.js app to Hostinger's managed
Node.js hosting ("Unlimited" plan). It failed, and the reason is structural, not a config mistake:

- Hostinger's shared Node servers run **glibc 2.28** (confirmed with `ldd --version`). Next.js 16's
  native SWC binary needs glibc 2.29+, so Next falls back to the WebAssembly SWC build.
- With WASM SWC, `next.config.ts` fails to load (`ERR_MODULE_NOT_FOUND` on the compiled temp
  config), and Turbopack can't run at all.
- A workaround was proven locally — `next.config.ts` → `next.config.mjs` plus
  `next build --webpack`; the WASM build passed in ~40s at ~2.2 GB peak memory — but it was **not**
  merged. It would leave the site running Next in a fallback mode a future Next/Payload release
  could break again, `sharp` (image processing) was still unverified on that glibc, and the build
  sat close to the plan's 3 GB RAM. For an image-heavy blog that a non-developer has to maintain,
  that risk wasn't acceptable.

WordPress on the same plan has none of these problems, and the wife's Pinterest-marketing course
teaches Hostinger + WordPress, so she can follow it directly.

## What the AI builder got wrong

The Hostinger AI builder takes 2000-character prompts (the prompts used are in
[`ai-builder-prompts.md`](ai-builder-prompts.md)). Its first pass kept the palette roughly but ignored most
of the spec, and made several mistakes that were fixed by hand:

- Put the wife's **personal email and a fake phone number** in the footer and the Contact page (plus
  a fake "Example avenue 100" address). All removed; the public address is `hello@wellwithher.com`.
- Created the four categories as **plain pages**, so every "category" page listed every post. Fixed
  with real post categories (below).
- Skipped the Privacy Policy, the Affiliate Disclosure, and the cookie banner.
- Pointed the sample posts' featured images at Unsplash URLs without importing them, so they didn't
  render. Re-imported into the media library.

## What was built

All of this was done through the WordPress REST API / Site Editor, so it's all editable from
`wp-admin` — nothing lives in theme files.

### Design (global styles)

Appearance → Editor → Styles. Mirrors `src/theme/palette.ts` and `src/theme/typography.ts`:

- **Fonts:** Jost (body, buttons) and Parisienne (script accents) installed in the WordPress font
  library and self-hosted under `wp-content/uploads/fonts/` — no Google Fonts requests. Headings
  use the theme's bundled Playfair Display.
- **Palette:** the site colors (sage `#8a9678`, ink `#4a3222`, cream `#f8f2ea`, card `#fffaf3`,
  footer `#efe4d2`, …) added as custom palette entries, so they show up in the editor's color picker.
- **Buttons:** dark ink pill (`#4a3222`, 24px radius), matching the article CTA.
- **Custom CSS** (Styles → ⋮ → Additional CSS): every custom class is prefixed `wwh-`. Backup:
  `backup/global-styles.css`. Covers the sticky translucent header with the "WH" circle logo, the
  full-bleed home hero, the category icon row, the 3-column cream card grid, the category page
  header, the article layout, the beige footer, the legal pages, and the cookie banner.

### Templates

- **Single post** (`single`, customized): featured image hero → category label → 37px title →
  byline → body (17px / 1.85, blockquotes rendered as centered Parisienne pull quotes), with a
  sticky "About WellWithHer" card in a right column. Backup: `backup/single.html`.
- **Footer** (template part, customized): brand + tagline / Categories / Company (About, Contact,
  Privacy Policy, Affiliate Disclosure, Cookie Policy, Cookie settings) / Follow. Backup:
  `backup/footer.html`.
- The header template part is the builder's; it's restyled through CSS only.

### Content structure

- **Post categories** `womens-health`, `sleep`, `nutrition`, `wellness`, with the same descriptions
  as `src/constants/category.ts`. The four category pages (`/womens-health/` etc.) each run a Query
  Loop filtered to their category, so new posts appear automatically.
- **Home page:** hero image (`docs/design-reference/images/home-hero-banner.png`, media ID 88),
  category icon row (the same MUI icons the Next site uses, inlined as SVG), "Latest Articles"
  query loop (6 posts), and a visually-hidden H1 for SEO, as in the Next site.
- **Legal pages:** Privacy Policy (`/privacy-policy/`) and Affiliate Disclosure
  (`/affiliate-disclosure/`), with the text from `scripts/seed.ts`. Cookie Policy
  (`/cookie-policy/`) is generated by Complianz.
- **"Shop this pick" pattern** (unsynced pattern, "Shop this pick (affiliate button)"): FTC
  disclosure line + pill button with `target="_blank"` and `rel="sponsored noopener"`. The wife
  inserts it at the end of each post (+ → Patterns) and replaces the placeholder link. It's
  unsynced on purpose — each post needs its own store URL.

### Cookie consent (Complianz, free version)

Matches the consent model in `src/utils/consent.ts` and what the Privacy Policy promises:

- **Default law: EU (GDPR) = opt-in.** Complianz's "United States" option is opt-out (tracking on
  until refused), which would contradict our Privacy Policy. Nothing optional loads before a choice.
- **Respect Do Not Track / Global Privacy Control: on** (the policy promises GPC is honored).
- Services declared: YouTube and Vimeo (the video providers the Next site supported), Pinterest
  (as a social/advertising pixel), advertising scripts = yes, statistics via Google Tag Manager.
- **GTM is not inserted yet** — there's no container ID (`NEXT_PUBLIC_GTM_ID` was never set). The
  "Google data processing amendment" checkboxes were left unchecked: we can't assert anything about
  a Google account that doesn't exist yet.
- Banner copy is the Next site's: title "Your privacy choices", buttons Accept all / Reject all /
  Customize, categories Functional (always on) / Statistics / Marketing. Styled to the site via
  the global CSS, not the Complianz CSS editor.
- **Declined on purpose:** Complianz's "website scan" registration and tips newsletter (both would
  have sent the wife's personal email to Complianz), its cross-sell plugin installs, and the
  cookiedatabase.org connection (sends site data to a third party; there are no cookies to describe
  yet).
- Pro features (records of consent, data request forms, native Consent Mode V2, per-region rules)
  aren't needed at this size. Consent Mode V2 can be configured inside GTM itself when analytics is
  added.

## Open items

1. **Footer "Cookie settings" link doesn't reopen the banner.** It uses the class
   `cmplz-show-banner`, which Complianz's script doesn't listen for. The floating "Manage consent"
   tab (bottom right) does work, so visitors can still change their choice. Decide: find the
   selector Complianz actually uses, or drop the link.
2. **Hero image licensing:** the banner is the design-reference placeholder (`scripts/seed.ts` says
   to replace it with licensed photography before launch).
3. **`hello@wellwithher.com`:** confirm the inbox exists and that the Contact form delivers to it.
4. **Pinterest / Instagram footer links** are plain text until the profiles exist.
5. **Analytics:** create the GTM container, add its ID in Complianz → Wizard → Statistics
   configuration (Complianz then injects GTM, blocked until consent), and set the GA4 and Pinterest
   tags in GTM to fire only on consent.
6. **Domain:** attach the real domain, then set permalinks to `/%category%/%postname%/`. The old
   `/[category]/[pinId]/[slug]` URL shape isn't reproduced — only worth custom rewrite code if pins
   already point at old URLs.
7. **Wife's account:** give her the **Editor** role, not Administrator.
8. **Sample posts and images** from the AI builder (two "Wellness tech" posts, 530×250 images) are
   placeholders to delete once real posts exist.

## Restoring

If a theme update, a builder re-run, or an accidental edit wipes the customizations:

- **CSS:** paste `backup/global-styles.css` into Appearance → Editor → Styles → ⋮ → Additional CSS.
  (Global styles also keep revisions, under Styles → Revisions.)
- **Templates:** Appearance → Editor → Templates (or Patterns → Template parts) → open the template
  → ⋮ → Code editor, and paste `backup/single.html` or `backup/footer.html`.
- **Reverting to the builder's original:** the same menu has "Reset" for the single template and
  the footer part.

Keep the backups current: when a customization changes in WordPress, update the matching file here.
