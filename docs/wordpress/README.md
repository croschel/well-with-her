# HerWellChapter on WordPress (Hostinger)

The site is being rebuilt as a WordPress site on Hostinger so the wife can run it alone, without a
developer. This repo (Next.js + Payload) stays as the design and content reference, and as the
fallback if the WordPress version doesn't work out. This doc records why we moved, what was built
in WordPress, every non-obvious decision, and what's still open.

Snapshot as of 2026-10-10, updated 2026-10-15 for the rename.

**Rename (2026-10-15):** the brand was WellWithHer until 2026-10-15. It is now **HerWellChapter**,
because no matching domain was available, and the site lives at https://herwellchapter.com. The
repo name, the `wwh-` CSS prefix and the old Next.js code keep the old name on purpose. The old
Vercel site (still WellWithHer) stays up until every pin points at the new domain.

## Why WordPress (and not Next.js on Hostinger)

The goal was to cut hosting cost versus Vercel Pro (see [`hosting-decision.md`](hosting-decision.md)
for the cost comparison). The first attempt was deploying this Next.js app to Hostinger's managed
Node.js hosting ("Unlimited" plan). It failed, and the reason is structural, not a config mistake:

- Hostinger's shared Node servers run **glibc 2.28** (confirmed with `ldd --version`). Next.js 16's
  native SWC binary needs glibc 2.29+, so Next falls back to the WebAssembly SWC build.
- With WASM SWC, `next.config.ts` fails to load (`ERR_MODULE_NOT_FOUND` on the compiled temp
  config), and Turbopack can't run at all.
- A workaround was proven locally — `next.config.ts` → `next.config.mjs` plus
  `next build --webpack`; the WASM build passed in ~40s at ~2.2 GB peak memory — but it was **not**
  merged. It would leave the site running Next in a fallback mode a future Next/Payload release
  could break again, `sharp` (image processing) was still unverified on that glibc, and the build
  sat close to the plan's 3 GB RAM. For an image-heavy blog that a non-developer has to maintain,
  that risk wasn't acceptable.

WordPress on the same plan has none of these problems, and the wife's Pinterest-marketing course
teaches Hostinger + WordPress, so she can follow it directly.

## Where things are

- **Site URL:** https://herwellchapter.com (attached 2026-10-15). Before that the site ran on the
  Hostinger temporary domain `palevioletred-hornet-247825.hostingersite.com`.
- **Theme:** `hostinger-ai-theme` (a Gutenberg block theme), generated by Hostinger's AI site
  builder and then restyled by hand. **Editor: Gutenberg**, not Elementor — Elementor's free tier
  can't template single posts (needs Pro, ~US$59/yr), it adds page weight that hurts mobile
  Pinterest traffic, and it's one more plugin to keep updated.
- **Backups:** Hostinger takes a daily backup of the whole site (files + database; hPanel →
  Backups). Separately, every design customization is copied in `docs/wordpress/backup/` (see
  "Restoring" below) — useful when a problem is noticed too late for the daily backups, or when
  only the design needs rolling back. Posts, media, the legal pages and the Complianz settings are
  only in Hostinger's backups.

## Working on the site with Claude Code

Changes to the live site go through the **`herwellchapter-wordpress`** agent
(`.claude/agents/`), which drives the user's logged-in Chrome tab. It preloads two project skills:

- **`wordpress-chrome`** (`.claude/skills/wordpress-chrome/`): IDs and endpoints, REST edit
  recipes, the SEO custom-field and media-upload paths, cache purge, public verification, and the
  safety rules (privacy, what needs confirmation).
- **`wordpress-backup-sync`** (`.claude/skills/wordpress-backup-sync/`): checks `backup/` against
  the live site by SHA-256 (`scripts/live-hashes.js` in the browser, then
  `scripts/compare_hashes.py`), and says how to bring a stale file and this README up to date.

The older agents (`wellwithher-feature`, `wellwithher-debugger`, `seo-auditor`) only cover the
legacy Next.js code.

## Architecture

Measured on 2026-10-10 (HTTP headers, WordPress REST API, Site Health, hPanel).

```
Visitor (Pinterest / Google)
  → DNS: herwellchapter.com (A records on the Hostinger CDN; www → www.herwellchapter.com.cdn.hstgr.net)
  → Hostinger CDN ("hcdn" edge servers)
  → shared Hostinger server: LiteSpeed web server + LiteSpeed Cache
      ├─ PHP 8.3 → WordPress 7.1.3 (Hostinger AI theme 2.1.13)
      ├─ MySQL (Hostinger-managed, same account) ≈ 5 MB
      └─ disk: wp-content/uploads (media + self-hosted fonts)
```

| Layer      | What it is                                                        | Notes                                                                                                            |
| ---------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Hosting    | "Unlimited Web Hosting", shared server                            | 0.89 / 50 GB disk, 23K / 600K inodes, 1 / 1000 sites; ~1% CPU over 24 h. glibc 2.28 (why Next.js can't run here) |
| Web server | LiteSpeed + LiteSpeed Cache plugin                                | Pages are served from the page cache (`x-litespeed-cache: hit`)                                                  |
| CDN        | Hostinger CDN, included in the plan                               | Pages `max-age=604800` (7 d), media `max-age=31536000` (1 y)                                                     |
| App        | WordPress 7.1.3, PHP 8.3, Gutenberg                               | Design is global styles + templates in the database, no theme files edited                                       |
| Database   | Hostinger MySQL                                                   | Replaces Neon for this site                                                                                      |
| Backups    | Hostinger daily backups (whole site) + design copies in `backup/` |                                                                                                                  |

**Media.** Stored on the server's disk under `wp-content/uploads/<year>/<month>/` — no external
bucket (the Vercel Blob is only used by the old Next.js site). 40 images, all PNG/JPEG. WordPress
generates 7 extra sizes per upload (thumbnail, medium, medium_large, large, 1536×1536 and the
theme's `blog-thumb`/`blog-full`), so 81 MB of originals take 168 MB on disk. Pages use
`srcset`, so browsers pick a size for their screen; delivery goes through the Hostinger CDN.

**Known weak spot: image weight.** The imported images are PNG at 1.5–2.5 MB each, and no WebP is
served (a request with `Accept: image/webp` still gets the 2.46 MB PNG). In one test the CDN
bypassed the cache for a full-size image (`x-hcdn-cache-status: BYPASS`) and the origin took ~5 s to
respond. Converting to WebP/compressing is the main performance fix (open item 10).

|               | Before (Next.js)                   | Now (WordPress)             |
| ------------- | ---------------------------------- | --------------------------- |
| App           | Next.js 16 + Payload CMS on Vercel | WordPress on Hostinger      |
| Database      | Neon Postgres (external)           | MySQL on the same account   |
| Media         | Vercel Blob (external)             | Server disk + Hostinger CDN |
| Caching       | ISR + on-demand revalidation       | LiteSpeed Cache + CDN       |
| Maintained by | A developer                        | The wife, from wp-admin     |

## What the AI builder got wrong

The Hostinger AI builder takes 2000-character prompts (the prompts used are in
[`ai-builder-prompts.md`](ai-builder-prompts.md)). Its first pass kept the palette roughly but ignored most
of the spec, and made several mistakes that were fixed by hand:

- Put the wife's **personal email and a fake phone number** in the footer and the Contact page (plus
  a fake "Example avenue 100" address). All removed; the public address is now
  `hello@herwellchapter.com` (was `hello@wellwithher.com`).
- Created the four categories as **plain pages**, so every "category" page listed every post. Fixed
  with real post categories (below).
- Skipped the Privacy Policy, the Affiliate Disclosure, and the cookie banner.
- Pointed the sample posts' featured images at Unsplash URLs without importing them, so they didn't
  render. Re-imported into the media library.

## What was built

All of this was done through the WordPress REST API / Site Editor, so it's all editable from
`wp-admin` — nothing lives in theme files.

### Design (global styles)

Appearance → Editor → Styles. Mirrors `src/theme/palette.ts` and `src/theme/typography.ts`:

- **Fonts:** Jost (body, buttons) and Parisienne (script accents) installed in the WordPress font
  library and self-hosted under `wp-content/uploads/fonts/` — no Google Fonts requests. Headings
  use the theme's bundled Playfair Display.
- **Palette:** the site colors (sage `#8a9678`, ink `#4a3222`, cream `#f8f2ea`, card `#fffaf3`,
  footer `#efe4d2`, …) added as custom palette entries, so they show up in the editor's color picker.
- **Buttons:** dark ink pill (`#4a3222`, 24px radius), matching the article CTA.
- **Custom CSS** (Styles → ⋮ → Additional CSS): every custom class is prefixed `wwh-`. Backup:
  `backup/global-styles.css`. Covers the sticky translucent header with the logo mark (below), the
  full-bleed home hero, the category icon row, the 3-column cream card grid, the category page
  header, the article layout, the beige footer, the legal pages, and the cookie banner.
- **Logo and site icon:** the wife's "HC" monogram (thin ink circle + sage leaves). Site icon
  (Settings → General → Site Icon, used for the favicon and the admin bar) is media 197
  `herwellchapter-icon.png`, cropped tight around the circle so the letters read at 16 px, on a
  cream background so it works on dark browser tabs. The header and the About card use media 212
  `herwellchapter-logo-mark.png`, the same crop with a transparent background, set as a CSS
  background (header `::before`, `.wwh-logo`). It replaced the old "WH" text circle.

### Templates

- **Single post** (`single`, customized): featured image hero → category label → 37px title →
  byline → body (17px / 1.85, blockquotes rendered as centered Parisienne pull quotes), with a
  sticky "About HerWellChapter" card in a right column (logo mark on top, bio written by the wife).
  Backup: `backup/single.html`.
- **Footer** (template part, customized): brand + tagline / Categories / Company (About, Contact,
  Privacy Policy, Affiliate Disclosure, Cookie Policy, Cookie settings) / Follow. Backup:
  `backup/footer.html`.
- The header template part is the builder's; it's restyled through CSS only.

### Content structure

- **Post categories** `womens-health`, `sleep`, `nutrition`, `wellness`, with the same descriptions
  as `src/constants/category.ts`. The four category pages (`/womens-health/` etc.) each run a Query
  Loop filtered to their category, so new posts appear automatically.
- **Home page:** hero image (media 193, swapped in by hand by the user for the new brand; the
  original was `docs/design-reference/images/home-hero-banner.png`, media 88), category icon row
  (the same MUI icons the Next site uses, inlined as SVG), "Latest Articles" query loop (6 posts), and a visually-hidden H1 for SEO, as in the Next site. Saving the page in
  the editor during the banner swap dropped the `<!-- wp:html -->` wrapper around the icon row, so
  the editor now shows it as a Classic block. It still renders the same; the backup matches the
  live markup.
- **Legal pages:** Privacy Policy (`/privacy-policy/`) and Affiliate Disclosure
  (`/affiliate-disclosure/`), with the text from `scripts/seed.ts`. Cookie Policy
  (`/cookie-policy/`) is generated by Complianz.
- **"Shop this pick" pattern** (unsynced pattern, "Shop this pick (affiliate button)"): FTC
  disclosure line + pill button with `target="_blank"` and `rel="sponsored noopener"`. The wife
  inserts it at the end of each post (+ → Patterns) and replaces the placeholder link. It's
  unsynced on purpose — each post needs its own store URL.

### Cookie consent (Complianz, free version)

Matches the consent model in `src/utils/consent.ts` and what the Privacy Policy promises:

- **Default law: EU (GDPR) = opt-in.** Complianz's "United States" option is opt-out (tracking on
  until refused), which would contradict our Privacy Policy. Nothing optional loads before a choice.
- **Respect Do Not Track / Global Privacy Control: on** (the policy promises GPC is honored).
- Services declared: YouTube and Vimeo (the video providers the Next site supported), Pinterest
  (as a social/advertising pixel), advertising scripts = yes, statistics via Google Tag Manager.
- **GTM is not inserted yet** — there's no container ID (`NEXT_PUBLIC_GTM_ID` was never set). The
  "Google data processing amendment" checkboxes were left unchecked: we can't assert anything about
  a Google account that doesn't exist yet.
- Banner copy is the Next site's: title "Your privacy choices", buttons Accept all / Reject all /
  Customize, categories Functional (always on) / Statistics / Marketing. Styled to the site via
  the global CSS, not the Complianz CSS editor.
- **Declined on purpose:** Complianz's "website scan" registration and tips newsletter (both would
  have sent the wife's personal email to Complianz), its cross-sell plugin installs, and the
  cookiedatabase.org connection (sends site data to a third party; there are no cookies to describe
  yet).
- Pro features (records of consent, data request forms, native Consent Mode V2, per-region rules)
  aren't needed at this size. Consent Mode V2 can be configured inside GTM itself when analytics is
  added.

## Content import (2026-10-10)

All 11 published articles from production were imported as WordPress posts, with their images.

- **Source:** the production site's public Payload REST API
  (`https://well-with-her-peach.vercel.app/api/articles?depth=1`), cross-checked against the Neon
  `production` branch with read-only `SELECT`s (11 articles, 28 inline image blocks, 14 CTA
  blocks). Nothing in Neon or Vercel was modified.
- **Images:** downloaded by the browser straight from the Vercel Blob store's public URL
  (`https://<store-id>.public.blob.vercel-storage.com/<file>`, which sends
  `Access-Control-Allow-Origin: *`) and uploaded to the WordPress media library — 39 images, renamed
  from "Imagem do Codex …" to `<post-slug>-hero.png` / `<post-slug>-<n>.png`, alt text preserved.
  The Payload `/api/media/file/...` route can't be used for this: it sends no CORS origin header.
  The pre-resized Payload sizes were used (`hero` 1600px for featured images, `gallery` 1200px for
  inline images) rather than the multi-megabyte originals.
- **Conversion:** each article's Lexical JSON was converted to native Gutenberg blocks, so
  everything stays editable: headings, paragraphs, bold/italic, bullet lists, line breaks, images
  (`core/image`), and links. CTA blocks became either a `wwh-buy` button or, for `style: link`, a
  `wwh-cta-link` paragraph; both keep `rel="noopener sponsored"` and `target="_blank"`. The
  end-of-article `buyButtonUrl`/`buyButtonLabel` became the same disclosure line + button as the
  "Shop this pick" pattern.
- **Kept:** original publish dates, categories (9 Women's Health, 1 Wellness, 1 Nutrition; Sleep is
  empty in production too), and slugs, lowercased (`Saffron-isnt-just-Spice` →
  `saffron-isnt-just-spice`).
- **Not carried over:** `pinId` (WordPress URLs don't include it — see the redirect table below),
  and `ogImage`/`ogDescription`, `galleryImages` and `videoEmbedUrl`, which are empty on every
  production article.
- **Hostinger bug found:** creating a post through the REST API with `featured_media` already set
  returns a PHP fatal ("There has been a critical error on this website"), with any image. Creating
  the post first and setting `featured_media` in a second request works. Likely one of the
  Hostinger plugins hooking post creation; check whether the editor UI hits it too when the wife
  publishes her first real post.

## Restoring

If a theme update, a builder re-run, or an accidental edit wipes the customizations:

- **CSS:** paste `backup/global-styles.css` into Appearance → Editor → Styles → ⋮ → Additional CSS.
  (Global styles also keep revisions, under Styles → Revisions.)
- **Palette, fonts, button style:** `backup/global-styles.json` is the user global-styles record
  (`settings` + `styles`, without the CSS above). Restore it through the REST API from a logged-in
  admin tab on the Site Editor:
  `wp.apiFetch({path:'/wp/v2/global-styles/<id>', method:'POST', data:{settings, styles:{...styles, css}}})`
  (the id is in `/wp/v2/themes?status=active` → `wp:user-global-styles`). The font files it points
  at live in the font library (`wp-content/uploads/fonts/`); if they're gone, reinstall Jost and
  Parisienne first via Styles → Typography → Manage fonts.
- **Templates:** Appearance → Editor → Templates (or Patterns → Template parts) → open the template
  → ⋮ → Code editor, and paste `backup/single.html` or `backup/footer.html`.
- **Home and category pages:** open the page in the editor (Pages → Home / Women's Health / Sleep /
  Nutrition / Wellness) → ⋮ → Code editor, and paste the matching file from `backup/pages/`. The
  home references the hero image as media 193 and the category pages filter by category IDs
  5–8 (`womens-health`, `sleep`, `nutrition`, `wellness`); if those were recreated with new IDs,
  update them in the pasted markup.
- **Reverting to the builder's original:** the same menu has "Reset" for the single template and
  the footer part.

Keep the backups current: when a customization changes in WordPress, update the matching file here.
